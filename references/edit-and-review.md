# 剪辑、音画同步、字幕与成片全检

## 剪辑时间线

以通过单段审查的原始带音片段建立素材清单。每个 cut 记录原始文件哈希、source_in/out、timeline_in/out、video/audio track、速度、转场、角色/服装/场景状态、覆盖的剧本节拍和字幕 ID。原始素材保留，生成版本化 EDL 或剪辑工程，不能只交一个无法追溯的 MP4。

统一输出的分辨率、帧率、像素宽高比、音频采样率及声道。实际素材可与计划规格不同，先测量，再决定适配。对话默认不变速；需要变速时音视频联动，保持音调并复查口型。选择 OpenMontage 的实际合成工具，读取其 input_schema、阶段导演与相关 `.agents/skills`，复杂时间线不要凭空猜 `video_compose` 参数。

人物对白剪辑以完整语义、情绪与动作完成点为准。J/L cut 必须是有意的画外延续，记录说话人和声源，不把错位包装成艺术处理。动作接点看切前/切后；转场、BGM 不得掩盖被删掉的关键动作和台词。

## 音画与口型同步（必做）

1. **源段检查**：probe 音视频起始时间、时长和帧率。原生 H3 音频优先；全段实听，核对说话人、词句、音色、停顿、语气、环境声与动作声。生成有音轨不代表台词正确。
2. **逐句对齐**：建立 `dialogue_alignment.json`，每句记录角色、原剧本原文、实际听到的文字、source 音频起止、timeline 起止、可见嘴部/画外音、证据及状态。ASR 提供候选时间，不替代听辨；强制对齐只能对齐已说出的词，不能证明没有漏词或幻觉词。
3. **嘴型与发声者**：可见发言时检查起音、闭口音、停顿、句尾、说话人切换和双人同框串声；画外音不得要求画面中不说话的人动嘴。静帧无法证明嘴型同步，必须看连续片段并听对应声音。
4. **音效对齐**：脚步、落物、关门、击打等关键音效与可见事件逐点比对；相邻段的环境声底和混响符合空间，防止同一脚步被重复剪入。
5. **偏移定位**：常量偏移可以校正轨道起点；越往后越偏需查帧率/时间基、变速、采样率、转码时间戳。不要靠反复挪字幕修音画。可用项目自定 80ms 作为“触发复核”的起始阈值，它不是通用合格保证；肉眼明显不同步即失败。
6. **修复顺序**：先修裁切和时间戳 → 再修混音与可独立替换的音效 → 必要时按角色固定声线补配音 → 可见对白必须经实际可用的口型工具修复或重生成该段。未配置口型工具时说明限制，不能把 TTS 铺上去就宣告 lip-sync 完成。
7. **成片复检**：源段同步不能证明拼接后同步。检查每句对白、每个切点和全片头尾，防止音轨多一次剪切或累计漂移。记录对齐前后时间码。

TTS/口型/ASR 工具按 OpenMontage 注册表实际可用能力选择，不能默默调用新付费服务。角色声线留 voice_id、参考样本、语言/口音、速度与版本，生成批次间复用。保留对白/环境/音乐独立 stems（能实际分离时）；若原生音轨已含 BGM，不再重复叠相同音乐。无法干净分离时重生成或使用现有合格整轨。

混音保证对白可懂、无削波、切点无爆音；测量实际响度和 true peak，按用户平台要求定目标。项目未给指标时可以把 -16 LUFS / -1 dBTP 作为暂定制作目标，写清是项目选择而非平台法规。最后再完整听一次，仪表正常不能替代听辨。

## 字幕制作与合成（必做）

- 原文以校正过的剧本和最终实听对白为准。漏说、错说先修声音/画面，再出字幕；不能字幕写正确、人物却说错误内容。
- 用最终剪辑的对白时间点生成 UTF-8 SRT；ASS 负责字体、描边、背景和位置。SRT/ASS 内容与时间需同源生成，修正后同时再导出。
- 以语义和呼吸断句，通常每屏 1–2 行。按画幅、实际字号和阅读速度调整；不拆专名、数字单位或完整词组，不机械逐字滚动。中文可先以每行约 12–18 字试排，随后查看成片调节。
- 检查缺字/乱码、错别字、称呼、标点、简繁、说话人、重叠、倒序、负时间、超出片长。双人重叠对白须明确分层样式和规则，不能让默认底部字幕互盖。
- ASS 使用真实存在并可显示中文的字体。平台安全区、底部 UI 占位按用户目标配置；在实际 9:16 或 16:9 成片中查看，不拿设定图尺寸排字幕。
- 检查每条字幕在最终烧录画面中的断行、遮脸、盖关键道具、越界、闪现和提前消失。片头片尾、亮暗背景、人物低头/坐下的画面都要覆盖。
- 输出干净母版 `E01-master.mp4`、烧录版 `E01-subtitled.mp4`、`E01.srt`、`E01.ass`。可附软字幕版，但软字幕轨不能冒充已烧录版。

FFmpeg 烧录建议在项目临时导出目录中使用简单相对文件名如 `captions.ass`，从参数数组调用并设置 cwd，避免 Windows 盘符/冒号/单引号进入 subtitles filter 时多层转义。先确认 FFmpeg 带 `ass`/`subtitles` filter。选定视频编码和 AAC 等音频输出后明确 map 需要的流。烧录会重编码画面，导出完成再对最终文件全检。

## 四层检查与修复

| 层级 | 覆盖对象 | 必查 |
|---|---|---|
| 单镜 | 每个生成段从头到尾 | 同一个人/服装/道具，肢体变形、闪烁、穿模、动作完成、对白与口型 |
| 镜间 | 每一个切点及其前后连续片段 | 180°轴线、视线、左右手、动作方向、道具状态、光照、声音空间、台词接续 |
| 叙事 | 每场、每集及所有相邻集 | 原著因果、角色动机、信息先后、时空跳转、伏笔兑现、悬念接续 |
| 最终导出 | 母版与字幕版实际文件 | 全量解码、轨道/时长、全片视听、字幕版式、用户交付要求 |

问题单字段：`issue_id / episode / segment / time_in / time_out / category / severity / expected / observed / evidence / proposed_fix / status / verified_on_hash`。严重程度用 blocker（缺片/丢台词/无法播放等）、major（串脸/明显音画不同步/剧情矛盾等）、minor。blocker/major 未解决不能写“全检通过”；minor 可明示留作已知问题。

修复后重看问题区间和两侧切点；涉及时长、字幕或音轨时重验整集同步和字幕；跨集状态改变时继续检查下集。更新最终文件的哈希与所有过时报告。

## 终检证据与工具局限

技术证据可包括 ffprobe JSON、全流解码日志、黑场/静帧/静音候选时间段、响度测量、字幕解析和资产完整性。黑场、静帧或静音可能是剧情设计，不能自动判坏也不能自动忽略。运行诸如 `ffmpeg -v error -xerror -i <file> -map 0:v:0 -map 0:a:0 -f null -` 的全量解码；参数以实测音轨和当前 FFmpeg 为准，不以首帧 probe 代替解码。

视听证据要覆盖全片时间线：逐段播放/分析连续视频并听音轨，每个 cut 起中末帧与切点前后接触表帮助定位，不能把这些稀疏图片称作完整视频检查。ASR 不可用时可通过完整实听完成台词核对；完全没有音频感知能力则 audio/sync 只能 partial。

`verify_delivery.py` 的 pass 意味“机器检查通过且完整人工/模型检查记录已关联”，不是独立语义裁判。不要批量填空白的 pass 来满足它。任何无法实际覆盖的项目记录 partial、明确时间区间和原因，在最终交付中保留。全检也不承诺零瑕疵。
